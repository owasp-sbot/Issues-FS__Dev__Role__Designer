## Purpose

This proposal translates the interview synthesis into concrete, implementable design specifications for the Issues-FS Journalist website redesign (v2). Each proposal section provides specific values -- hex codes, font names, pixel dimensions, layout structures -- that the Dev role can implement against and the QA role can validate against.

The overarching goal: transform the site from a default Minima blog into a recognisable publication that matches the quality of its content.

## Proposal 1: Visual Identity & Branding

### Design Rationale

The Journalist's instinct that identity should be "earned, not imposed" is correct. The palette and typography below are derived from newsroom conventions -- muted, authoritative, high-contrast -- rather than from startup branding trends. The accent colour is singular and used sparingly, reserved for interactive elements and content-type signalling.

### Colour Palette

| Role | Name | Hex | Usage |
|------|------|-----|-------|
| **Primary** | Ink | `#1A1A2E` | Body text, headings, masthead background |
| **Secondary** | Slate | `#4A4A68` | Secondary text, bylines, metadata |
| **Accent** | Signal Blue | `#2563EB` | Links, interactive elements, primary CTA |
| **Accent Hover** | Deep Signal | `#1D4ED8` | Link hover, button hover states |
| **Surface** | Paper | `#FAFAF8` | Page background |
| **Surface Alt** | Warm Grey | `#F3F2EE` | Card backgrounds, code block backgrounds, section dividers |
| **Border** | Ash | `#D4D2CC` | Borders, horizontal rules, table lines |
| **Success** | Verified | `#16A34A` | Positive indicators, interview type accent |
| **Warning** | Amber | `#D97706` | Daily brief type accent, attention markers |
| **Danger** | Alert Red | `#DC2626` | Investigation type accent, corrections |
| **Muted** | Fog | `#9CA3AF` | Disabled states, tertiary text, correction type accent |

#### Contrast Verification

All text colours meet WCAG AA (minimum 4.5:1 contrast ratio against their intended backgrounds):

- `#1A1A2E` on `#FAFAF8` = 15.2:1 (AAA)
- `#4A4A68` on `#FAFAF8` = 7.1:1 (AAA)
- `#2563EB` on `#FAFAF8` = 4.6:1 (AA)
- `#FAFAF8` on `#1A1A2E` = 15.2:1 (AAA, for masthead inverse text)

```html

<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>

```

### Masthead Concept

The masthead uses a dark background (`#1A1A2E`) with inverse text (`#FAFAF8`), evoking the nameplate of a broadsheet newspaper. The title is uppercase, tracked wide, with a thin bottom border in Signal Blue to provide a subtle accent.

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│  ISSUES-FS NEWS                                                 │
│  ─────────────── (2px Signal Blue accent line)                  │
│  Journalism from inside the Issues-FS agentic ecosystem         │
│                                                                 │
│  Articles   Briefs   Interviews   Investigations   About   RSS  │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

Masthead CSS tokens:

- Background: `#1A1A2E`
- Text: `#FAFAF8`
- Tagline: `#9CA3AF` (Fog)
- Accent border: `#2563EB` (Signal Blue), 2px solid
- Padding: `24px 32px`
- Nav link colour: `#D4D2CC` (Ash), hover: `#FAFAF8`

### Spacing System

Base unit: `8px`. All spacing derives from this base.

| Token | Value | Usage |
|-------|-------|-------|
| `--space-xs` | `4px` | Inline spacing, badge padding |
| `--space-sm` | `8px` | Icon gaps, tight element spacing |
| `--space-md` | `16px` | Component internal padding |
| `--space-lg` | `24px` | Section padding, card padding |
| `--space-xl` | `32px` | Section gaps, major separators |
| `--space-2xl` | `48px` | Page section separation |
| `--space-3xl` | `64px` | Hero section vertical padding |

## Proposal 3: Content Type Differentiation

### Design Rationale

This is the highest-consensus, highest-impact design opportunity. Five content types currently render identically. The differentiation system below uses four visual channels -- colour, badge, icon, and layout -- to make content types instantly recognisable without requiring the reader to parse metadata text.

### Type Colour System

| Content Type | Accent Colour | Hex | Badge Background | Badge Text |
|---|---|---|---|---|
| **Article** | Signal Blue | `#2563EB` | `#EFF6FF` | `#1D4ED8` |
| **Daily Brief** | Amber | `#D97706` | `#FFFBEB` | `#B45309` |
| **Interview** | Emerald | `#16A34A` | `#F0FDF4` | `#15803D` |
| **Investigation** | Alert Red | `#DC2626` | `#FEF2F2` | `#B91C1C` |
| **Correction** | Fog Grey | `#9CA3AF` | `#F3F4F6` | `#6B7280` |

### Badge Component

Each content type is identified by a small uppercase badge that appears above the title on cards and at the top of article pages.

```css
.badge {
  display: inline-block;
  padding: 3px 10px;
  font-family: "IBM Plex Sans", system-ui, sans-serif;
  font-size: 11px;
  font-weight: 700;
  letter-spacing: 0.08em;
  text-transform: uppercase;
  border-radius: 3px;
}

.badge--article       { background: #EFF6FF; color: #1D4ED8; }
.badge--brief         { background: #FFFBEB; color: #B45309; }
.badge--interview     { background: #F0FDF4; color: #15803D; }
.badge--investigation { background: #FEF2F2; color: #B91C1C; }
.badge--correction    { background: #F3F4F6; color: #6B7280; }
```

### Icon System

Unicode glyphs serve as lightweight content-type icons that render without any asset pipeline. They appear alongside badges and in navigation lists.

| Content Type | Icon | Unicode |
|---|---|---|
| Article | Newspaper | U+1F4F0 or text glyph `[A]` |
| Daily Brief | Lightning | U+26A1 or text glyph `[B]` |
| Interview | Speech bubble | U+1F4AC or text glyph `[I]` |
| Investigation | Magnifier | U+1F50D or text glyph `[X]` |
| Correction | Pencil | U+270F or text glyph `[C]` |

**Recommendation:** Use the text glyph fallbacks (e.g., `[A]`, `[B]`) for consistency and accessibility. Emoji rendering varies across platforms; text glyphs are predictable and can be styled with CSS.

### Layout Variations by Type

Each content type receives a distinct layout template. All share a common base structure but differ in emphasis.

**Article layout (`_layouts/article.html`):**
- Full-width body text with generous line height (1.7)
- Summary displayed as a large sub-headline below the title
- Topics rendered as clickable tag pills
- Sources section at the bottom with styled citation blocks
- Left accent border: 4px `#2563EB`

**Daily Brief layout (`_layouts/brief.html`):**
- Compact layout -- no hero summary, no large headline treatment
- Date is the primary identifier (displayed prominently)
- Body text at slightly smaller size (16px vs. 18px)
- Bulleted structure preserved; no long-form typographic treatment
- Left accent border: 4px `#D97706`

**Interview layout (`_layouts/interview.html`):**
- Q&A formatting with alternating background for questions vs. answers
- Question text: IBM Plex Sans, weight 600, colour `#1A1A2E`
- Answer text: IBM Plex Serif, weight 400, colour `#4A4A68`
- Participant names displayed in metadata header
- Left accent border: 4px `#16A34A`

**Investigation layout (`_layouts/investigation.html`):**
- Full-width like articles but with a more urgent visual tone
- Top banner: `#FEF2F2` background with "INVESTIGATION" label
- Key findings section highlighted in a callout box
- Sources receive prominent treatment
- Left accent border: 4px `#DC2626`

**Correction layout (`_layouts/correction.html`):**
- Minimal layout -- compact, direct
- Links to the corrected article displayed prominently
- Correction date and original publication date both shown
- Muted visual tone: no accent colour prominence
- Left accent border: 4px `#9CA3AF`

## Proposal 4: Navigation & Information Architecture

### Design Rationale

The current site has no navigation beyond the default Minima header. As the content library grows (projected 30-50 pieces within a month), structured navigation becomes essential. The IA is derived directly from the five collections already defined in `_config.yml`.

### Top Navigation Bar

Located within the masthead, below the site title and tagline.

```
Articles   Briefs   Interviews   Investigations   About   [Search]
```

| Property | Value |
|----------|-------|
| Font | IBM Plex Sans, 15px, weight 500 |
| Colour | `#D4D2CC` (Ash) |
| Hover colour | `#FAFAF8` (Paper) |
| Active indicator | 2px bottom border in `#2563EB` (Signal Blue) |
| Spacing | `24px` between items |
| Search icon | Magnifier glyph, right-aligned |

**Active state:** The nav item for the current section receives a `#FAFAF8` text colour and a 2px bottom border in Signal Blue. This provides orientation without requiring breadcrumbs on every page.

### Category Landing Pages

Each collection needs an index page (e.g., `/articles/`, `/briefs/`) with:

- Page title matching the category name
- Collection description (one line explaining what this type contains)
- Reverse-chronological list of all items in that collection
- Each item displayed as a card with badge, title, summary, date, and topics
- Item count displayed below the page title

### Breadcrumbs

Displayed on article pages, below the masthead and above the article title.

```
Home  >  Articles  >  [Article Title]
```

| Property | Value |
|----------|-------|
| Font | IBM Plex Sans, 13px, weight 400 |
| Colour | `#9CA3AF` (Fog) |
| Separator | `>` character, colour `#D4D2CC` |
| Current page | Not linked, colour `#4A4A68` |
| Padding | `12px 0` above article title |

### Topic Tags and Filtering

Topics from front matter are rendered as clickable pill-shaped tags. Clicking a topic navigates to a topic page listing all content tagged with that topic.

| Property | Value |
|----------|-------|
| Tag shape | `border-radius: 12px; padding: 4px 12px;` |
| Background | `#F3F2EE` (Warm Grey) |
| Text | IBM Plex Sans, 12px, weight 500, colour `#4A4A68` |
| Hover | Background `#E5E4E0`, text `#1A1A2E` |
| Margin | `4px` between tags |

### Footer Navigation

A simple footer that repeats key links and adds supplementary navigation.


| Property | Value |

## Proposal 7: Interactive Features

### Design Rationale

Interactive features are sequenced by value-to-complexity ratio. All features must degrade gracefully -- the site must remain fully functional with JavaScript disabled (the static content renders from Jekyll, not from JS). Interactive features enhance, not enable.

### 7.1 Client-Side Search (Lunr.js)

**Complexity:** Medium
**Phase:** Phase 3

Search enables discovery as the content library grows beyond manual browsing (projected at 30-50 articles within a month).

**Implementation approach:**
- Generate a `search.json` at build time via a Jekyll template that indexes title, summary, topics, type, and body text
- Load Lunr.js (`~8KB gzipped`) and build the index on first search interaction (lazy loading)
- Search page at `/search/` with a dedicated search input
- Search icon in the navigation bar links to `/search/` and optionally triggers an inline search overlay on desktop

**Search UI specification:**

### 7.2 Topic Filtering

**Complexity:** Simple
**Phase:** Phase 2

On collection pages (`/articles/`, `/briefs/`, etc.), display a row of topic pills at the top. Clicking a topic filters the visible list to items that match.

**Implementation approach:**
- Pure CSS/JS toggle: add/remove a `.hidden` class on article cards
- No page reload required
- "Show all" button to clear the filter
- Active topic pill receives `background: #2563EB; color: #FAFAF8;`

### 7.3 Dark Mode Toggle

**Complexity:** Medium
**Phase:** Phase 3

A toggle in the masthead switches between light and dark themes. Preference is stored in `localStorage` and respects `prefers-color-scheme` as the default.

**Dark mode palette:**

| Role | Light Value | Dark Value |
|------|-------------|------------|
| Background | `#FAFAF8` | `#121220` |
| Surface | `#F3F2EE` | `#1E1E32` |
| Text Primary | `#1A1A2E` | `#E5E5EA` |
| Text Secondary | `#4A4A68` | `#A0A0B8` |
| Border | `#D4D2CC` | `#2E2E48` |
| Accent | `#2563EB` | `#60A5FA` |
| Code background | `#F3F2EE` | `#1E1E32` |

**Toggle UI:**
- Position: right side of masthead nav
- Icon: Sun/moon glyph (text-based for consistency)
- Touch target: `48px x 48px`
- Transition: `200ms` on background-color and color properties

**Implementation approach:**
- CSS custom properties for all colour values
- `.dark-mode` class on `<html>` element
- JS toggles the class and stores preference in `localStorage`
- On page load, check `localStorage` then `prefers-color-scheme`, apply before first paint to prevent flash

### 7.4 RSS Visibility

**Complexity:** Simple
**Phase:** Phase 1

The existing `jekyll-feed` plugin generates an RSS feed, but it is not visible to readers.

**Implementation:**
- Add an RSS icon/link in the masthead navigation (rightmost position)
- Add RSS link in the footer
- On the About page, explain that RSS is available for following updates
- Icon: text `RSS` in a small bordered badge, colour `#D97706` (Amber)

## Design Principles Summary

These principles guide all decisions in this proposal and should be referenced during implementation review:

1. **Content first.** The design serves the writing. Typography and whitespace are the primary design tools, not decoration.

2. **Semantic colour.** Every colour has a reason. The five content types map to five accent colours. Grey is for metadata. Blue is for interaction. There is no colour for "looking nice."

3. **Dual readability.** Content must read well in both Jekyll and GitHub markdown. Design lives in layouts and CSS, never in content files.

4. **Progressive enhancement.** The site works without JavaScript. Interactive features (search, filtering, dark mode) enhance but never gate content.

5. **Restrained identity.** The visual identity should feel inevitable -- as if it emerged from the content rather than being applied to it. One accent colour per content type. No gratuitous visual effects.

6. **Accessible by default.** AA contrast ratios, semantic HTML, skip links, 48px touch targets, readable fonts at every viewport.
